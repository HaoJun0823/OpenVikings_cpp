# Raw x87 status capture and nonwaiting clear - 2026-10-11

Original Windows entry 004F1FF2 executes FNSTSW into a WORD, FNCLEX, then returns the old WORD sign-extended to EAX. Unlike _clearfp's abstract return, this includes TOP, condition codes, stack-fault, exception summary and the busy bit. This leaf is reconstructed as Runtime_ClearX87StatusRaw, and the existing floating-point initializer uses it at its final exception-clear step. Its ignored return does not alter startup behavior.

The C++ adapter uses the documented _fxsave intrinsic into a 16-byte-aligned 512-byte state area, then reads the signed status WORD at +2. FXSAVE neither waits for pending x87 exceptions nor clears/register-loads the x87 state. The existing _clearfp API clears x87 exceptions; the complete MXCSR is saved/restored so SSE exception flags and control remain intact. No FXRSTOR is used, avoiding unnecessary restoration or tag reconstruction. No inline assembly or additional CRT/library dependency is introduced; _clearfp was already used by startup.

The installed x86 debug UCRT from Windows Kit 10.0.26100.0 has _clearfp at RVA 0015CBA0 and performs FNSTSW/FNCLEX at 1015CBA9/1015CBAC, with no preceding FWAIT. The current x86 system release UCRT has _clearfp at RVA 00076E20 and performs FNSTSW/FNCLEX at 10076E29/10076E2C, also without FWAIT. Both subsequently clear SSE flags, which the adapter restores. These are read-only binary checks, not game builds or test execution. Their behavior agrees with Microsoft's documented exception/busy-bit clear. Original semantics still come from Game.exe; these host checks establish the adapter API match.

The current v145 Win32 project does not select /arch:IA32; MSVC's default is SSE2. FXSAVE/FXSR and MXCSR are available on that existing baseline. No new historical-Pentium compatibility promise is made and no x64 migration occurs. If a future project configuration deliberately selects IA32 without FXSR, it will need a separate documented state-capture adapter.
