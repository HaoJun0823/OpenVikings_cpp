# Remaster runtime

On October 16, 2026 the user authorized replacing the reconstructed CRT, compiler-support and x87 machinery on `remaster`. [XRuntime.cpp](../src/XRuntime.cpp) now delegates shared services to the supported MSVC runtime, UCRT, C++17 library and documented Windows APIs. The frozen legacy branch retains the original implementation and its evidence.

## Current implementation

- The hosting MSVC startup owns heap setup, thread-local runtime state, descriptors, environment, compiler exception handling, static initialization and process shutdown. [WinMain.cpp](../src/WinMain.cpp) runs only the game's explicit application initializers, in their existing order, then calls the game entry with the hosted WinMain arguments.
- Project allocation wrappers use `malloc`/`free` from the same hosting runtime. Zero-byte requests still obtain a freeable allocation. Placement-construction callers retain null-on-failure behavior and the existing allocation-failure callback through `_set_new_handler`/`_set_new_mode`. The reconstructed small-block heaps, lock tables and heap-selection environment variable are removed.
- Descriptor and stream operations use supported UCRT file functions. A small stable stream record preserves the existing pointer and EOF-flag contract for callers, including the deferred network implementation. Buffering, text translation and descriptor ownership belong to `FILE`. Closed wrapper records can be reused. Storage is initialized before WinMain, so application exit callbacks run before its destructor.
- Temporary streams use the Windows user-temp directory and delete-on-close handles transferred to UCRT descriptors/streams. This avoids the drive-root permissions required by traditional `tmpfile`. Failed ownership transfers close the resources they still own.
- String conversion, case comparison, formatting, sorting, random numbers, directory enumeration and exit callbacks use current runtime services. Memory-copy wrappers retain overlap support through `memmove`. Directory records retain 32-bit time/size fields and their 280-byte layout. File-size queries preserve the position and reject sizes outside the existing unsigned 32-bit API.
- Math callers use `std::sin`, `std::cos`, `std::atan` and `std::log10` directly. Float-to-integer conversion checks the signed 64-bit range and nonfinite values before casting; invalid values retain `INT64_MIN`. Signed wrapping-integer reinterpretation remains an explicit bit copy.
- Sprite transparency, sprite brightness and packed Gouraud shading use SSE2 integer operations instead of MMX. Obsolete `EMMS` calls, MMX processor detection and MMX dispatch names are removed through RM028. Both configurations explicitly use SSE2 and `/fp:precise`; no unit requires IA32/strict or raw tail-jump compiler overrides.

The historical [XCrtFileAccess.h](../src/XCrtFileAccess.h) include name remains as a small declaration facade, keeping existing callers stable. It no longer declares reconstructed CRT internals or mutable legacy runtime globals. `XCrtFileAccess.cpp`, `XCrtCompiler.cpp`, `XCrtMath.cpp` and `XCrtStartup.h` are removed from source and project/filter registration.

## Behavioral scope

This is an intentional runtime replacement, RM027, rather than a claim of bit-for-bit equivalence to the original CRT. Library math may differ in final rounding, exceptional inputs, floating-point status and NaN handling. SSE2 double intermediates do not reproduce x87 extended precision. Win32's normal floating-point return ABI may still use x87 registers; the project no longer manages their stack or discovers private math leaves. Sorting equal keys may produce a different order. Error wording, malformed numeric-input handling and low-memory diagnostics follow the current runtime. Bounded formatting retains the legacy `_vsnprintf` count/truncation contract; callers requiring termination reserve and write their final byte.

Game/save structures, serialized formats, application initializer order and the separate game simulation RNG are unchanged. No network source, protocol, transfer algorithm or synchronization policy is changed. Shared services also serve existing network callers; the stream EOF field is retained for that reason. Cross-version multiplayer determinism is not established by this migration and remains part of the deferred network project.

## Evidence and verification

Windows evidence establishes the old boundary contracts: startup `004E709E`, allocation wrapper `004E5DDD`, exit registration `004E5FC2`, overlap-capable memory copy `004E6170` and truncation `004E6F4C`. The earlier implementations and caller context remain in Git at `5e5235a`. The [backend evidence inventory](RUNTIME_BACKEND_EVIDENCE.csv) is historical evidence for removed bindings, not current dependencies. No behavior is inferred from Mac offsets.

Supported library references: [MSVC SSE2 selection](https://learn.microsoft.com/en-us/cpp/build/reference/arch-x86), [allocation-failure callbacks](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/set-new-handler), [exit callbacks](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/onexit-onexit-m) and [temporary-file limitations](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/tmpfile).

At the RM027 checkpoint, all 304 production units passed Win32 MSVC syntax-only checking with SSE2 and `/fp:precise`; ten final changed units also passed `/W4` without warnings. RM028 removes the CPU-detection unit, leaving 303 implementation units and 285 headers; all 303 pass SSE2/precise syntax checks, with the six affected units also passing warning-free `/W4`. The aggregate checkpoint retained two pre-existing signed/unsigned warnings in `C2EngineMacroMaps.cpp` and `C2VehicleLifecycle.cpp`. Project/filter/source parity, removed-backend references, caller coverage and frozen-legacy integrity are checked separately. No Debug/Release build, linking, new tests or game execution was performed. Startup/shutdown, save/load, rendering, audio and exceptional allocation/I/O behavior remain runtime-validation targets.
