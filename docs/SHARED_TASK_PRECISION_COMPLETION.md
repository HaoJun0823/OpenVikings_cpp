# Shared AI task entries and floating-point precision wrapper - 2026-10-11

Six previously unmapped Windows entries are reconstructed. See [SHARED_TASK_PRECISION_NATIVE_ENTRIES.csv](SHARED_TASK_PRECISION_NATIVE_ENTRIES.csv). The two AI manager wrappers previously assigned to system/shared helpers are implemented together with their complete direct task/default-position helper tree. These five entries belong to AI; no original address is removed from the global inventory. C2AITaskAccess.cpp/.h are registered in both project and Logic filters.

The main-task array has 50 records of 0x44 bytes, starting at handler+0x1C30. The type DWORD at record+8 determines whether a slot is occupied. Finding a slot updates the highest index at +0x1C2C before validation; a rejected task therefore retains that side effect. Types 1, 2, 3 and 5 require a non-border primary packed MIG point at +0xC; type 2 also requires the secondary point at +0x1C to pass. Other types are copied without added validation, matching Windows. The copy proceeds forward through 17 DWORDs, preserving native overlap behavior, then sets handler byte +6. Failure returns FFFFFFFF; the manager converts this to false and returns false for a missing player handler. Player lookup remains unchecked as in the original.

The soldier default-position helper rejects a border point before querying its micro-point continent type. A zero continent type rejects the update. Accepted updates write active byte +0xA32C, packed point DWORD +0xA32E and radius DWORD +0xA334 in that order, preserving intervening bytes. The manager forwards those parameters and the boolean result. Existing map conversion, border and continent accessors are used by their established names; no guessed coordinate clamp or terrain fallback is introduced.

Windows xrefs establish that the missing AI configuration loader at 0040822E and the wider AI scheduler use these entries. Those parents remain unresolved. This completes the direct callable block, not the full AI scheduler or configuration parser. No fake parser/scheduler connection or gameplay completion claim is added. The Mac header confirms the five original names; all layout, slot limits, branching, ordering and constants are established from Windows assembly and Game.exe.

The existing floating-point initializer at 004E6EFC now invokes the separate original precision wrapper at 004EB923. The wrapper forwards abstract control value 0x10000 and mask 0x30000 to the established 004F0570 adapter and returns its result. These bits select 53-bit double precision; rounding, exception masks, infinity control and SSE state are not added to the mask. Initialization call order remains callback initialization, Pentium adjustment, precision setting and x87 exception clear. This is extraction of an already working action, not a new math implementation. Legacy x87 stack-entry, status and math-error dispatch routines remain open.

The SPoint copy entry 00439842 is behaviorally represented by existing implicit trivial C++ copies. It remains open in the explicit native-entry inventory. Replacing the aggregate with a user-provided copy constructor would affect widespread initialization and is not justified merely to change the counter.
