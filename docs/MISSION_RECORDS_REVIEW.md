# Mission manager, goals and result records

Named the mission manager's current briefing ID, won/failed/interruption and submap transition flags, submap campaign/map IDs, mission count and mission array. Its physical Windows size is 531,628 bytes, containing 150 records of 3,544 bytes. Each mission has the 30-character debug text region with six unclassified bytes, visible/fulfilled/active flags, activation tick, original active flag, description ID, match mode, 30 goal records and 30 result records. Unknown bytes remain explicit.

Loading, goal evaluation, results, GUI mission/exit consumers, save/load and checksum use the same definitions. The embedded constructor begins at the first mission's visible-state region: manager +64 is mission +36, so its relative goal/result offsets 24/1,228 correspond to physical mission offsets 60/1,264. These relative offsets are separate from the physical record namespace.

The existing 40-byte goal representation is retained. Windows writes a fulfilled byte at +36, overlapping the low byte of its last represented parameter word. The status offset is named and asserted without changing that representation or introducing a new parameter-count assumption. Result records remain 76 bytes and keep their unchecked parameter accessor.

Windows evidence: construction/loading `0041CF58..0041D24A`, goal/evaluation code `0041E2AE..0041F8FA`, result code `0041F9F7..00422E42`, parameter accessor `00422FDB..00422FE5` and activation `00449F2D..00449F47`. Jump-table data is excluded from instruction counts. Preserved: member construction before clearing, complete raw serialization/checksum including unused slots and padding, registration and load-version paths, inactive skipping and goal order, timed/random goal reset and RNG order, result order, activation-before-results behavior, interruption/parent-return/submap precedence and caller return behavior after transitions. GUI-manager locals are excluded from mission-manager field substitution. Mac supplies original names only.

Validation: exact staged source/token equivalence, 37 literal value/type comparisons, 31 physical size/offset assertions, six affected production units and the private assertion unit passing Win32 `/Zs`, and 6,417 decoded instruction byte comparisons with original `Game.exe`. The companion CSV records named references. Existing actor/map/static-data offsets in individual predicates/results remain separate review targets; this record block does not claim a new complete behavioral audit of every action.
