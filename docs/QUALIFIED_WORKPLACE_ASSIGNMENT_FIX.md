# Qualified workplace assignment - 2026-10-14

The user reports that a collector who has unlocked potter, mason or another profession through experience still receives only a worker assignment when right-clicking the corresponding building. The expected single-human action changes the profession before assigning its workplace.

Windows `00435605`, specifically the building branch at `00435B50..00435C0C`, calls `0042D96C` at `00435B8F`. This is `Human_IsAbleToDoJob`: it reads the unlocked job flag at human +`15C` and applies the weapon restrictions for military professions. The C++ selector incorrectly called `Human_DoesEducationAllowJobChange` (`0042D912`), excluding experience-qualified humans who had not reached the education requirement. The selector now calls the existing correct predicate for every primary building profession, retaining the original action availability, current workplace/job, worker-capacity and queued-trader exclusion checks.

The existing unlock path accepts experience or education and sets `AllowedJobFlags`. It does not automatically turn a collector into a potter or mason on gaining experience; it makes the profession available. The corrected selector returns action 24 and prepares network command 21 with the target job, followed by command 28 with the house ID and revision. `WorldDisplayElement_DoDefaultAction` already submits those two commands in that order. Group selection retains its separate Windows behavior, which does not perform this single-human automatic change.

The contextual mouse tooltip already recognizes action 24 and the 21/28 pair. Its concatenation incorrectly used plain spaces. Windows `004BB8FC` loads string address `0050071C`, whose bytes in `Game.exe` are `20 2D 20 00` (" - "). Restoring that separator after the human name, before the target job and before action 16 produces the localized `<Name> - <change job> - <profession> - <assign workplace>` description. Other contextual human actions also retain the native separator after the name. Localized action/job strings continue to come from the existing string tables.

Windows ASM and `Game.exe` confirm the predicate, fields, command order and separator; Mac declarations only confirm existing semantic names. A private provenance audit checked 180 relevant Windows ASM instruction byte sequences against `Game.exe`. Both changed translation units pass MSVC Win32 `/Zs`. No tests, Debug/Release project build or gameplay run occurred.
