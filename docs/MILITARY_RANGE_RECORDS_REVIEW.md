# Military range-result and landscape-list review — 2026-10-14

Authority: Windows assembly / `Game.exe`, 0043A114–0043AA22 for the six object-range/choice routines and 0043AAE7–0043AE65 for landscape choice, list construction, traversal, predicate, callback and insertion. Mac declarations confirm existing function names only; original landscape-list template/type identity remains unresolved.

Object results are eight bytes: a signed 32-bit object ID followed by unsigned distance. Landscape results have the same physical stride but a packed map coordinate as their first DWORD. These views now have distinct names. The twelve-byte landscape list retains count, capacity and owning allocation; its actual implementation class, allocation family and explicit cleanup remain unchanged.

Insertion retains discovery order for equal distances, the original capacity shift/truncation order and the last-distance cutoff. Human and vehicle iterators keep their distinct filters; hidden/adult handling is not generalized. Animals still include neutral player 20 unless it is the querying player; other searches use twenty regular players. Destroyed-house filtering remains before range/insertion checks. Unresolved animal iterator selector flags keep their existing explicit names.

Object-choice wrappers start eligibility at one, including the first candidate even when threshold addition wraps. Landscape choice starts at zero, preserving its original wrap/division behavior. Landscape traversal still takes maximum-distance steps on every ring, rather than the ring radius, and a full list stops traversal before the point predicate. The constructor initializes only each coordinate DWORD, not its distance. No guards, sorting replacements, allocation changes or merged routines were introduced.
