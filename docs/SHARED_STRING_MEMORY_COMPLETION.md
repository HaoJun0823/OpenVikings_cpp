# Shared string and memory primitives - 2026-10-11

Sixteen native Windows CRT entries have separate C++ definitions. Their full behavior is established from Windows assembly and Game.exe; available Mac header library symbols supply names only. The preserved per-entry inventory is [SHARED_STRING_MEMORY_NATIVE_ENTRIES.csv](SHARED_STRING_MEMORY_NATIVE_ENTRIES.csv). This completes this primitive group, not the entire system/shared category.

The group covers string copy/append/length, bounded copy/append and zero padding, unsigned comparison signs, byte/substring searches, native 16-bit wide strings, integer absolute value, memory comparison and both memory-copy entries. Empty patterns, a search for NUL, zero bounds/counts, exhausted bounds and INT32_MIN follow the native branches. String-copy and append have a real shared native tail at 004E5C91; its internal C++ helper is not counted as another original entry.

Both 004E6170 (memcpy) and 004E71F0 (memmove) explicitly choose backward copying for destination > source inside the source range. Each reconstructed entry retains that branch, byte alignment, DWORD copying, final bytes and the original destination return. They remain separate original functions. The native unrolled small-copy cases are expressed as loops with the same direction and data result. The inline DWORD tables were checked directly in Game.exe; disassembly lines that interpret their bytes as instructions are not behavior evidence.

The original comparisons return -1, 0 or +1, rather than the arithmetic byte difference. Native strncmp scans the first argument up to NUL or the requested bound before comparing the second argument. Bounded append ensures a final NUL but does not pad; bounded copy pads the remainder and adds no extra byte when its bound is exhausted. Wide-string bounds count 16-bit units.

Confirmed native call sites now use these helpers in CFile::WriteString, CStringArray string insertion, Runtime_DuplicateString, temporary-file name generation, runtime fatal-message formatting, heap-mode selection, time-zone names, multibyte-copy fallback and decimal-digit shifting. Other existing standard-library uses are not changed without inspecting their owning Windows call paths. No new external CRT dependency, production file, build or test project is introduced.

The three affected translation units XCrtFileAccess, XFile and XStringArray pass Win32 MSVC /Zs without diagnostics. No build, tests or game run occurred. Valid-buffer contents and public return behavior are reconstructed; timing, CPU flag state, unrolled instruction identity and exception instruction addresses are not equivalence claims. Existing unresolved math error/status adapters remain unfinished.
