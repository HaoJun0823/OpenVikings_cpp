## Masked response

Remaining flags start as input & 0x1F. The original priority chain is retained: invalid flag 8/mask 1, division flag 4/mask 4, overflow flag 1/mask 8, then underflow flag 2/mask 0x10. Only one of these four branches executes. Input inexact flag 0x10/mask 0x20 is handled independently afterward. Calls to the unresolved original status-generation entry receive raw x87 bits 1, 4, 8, 0x10 and 0x20, not the input flag numbering. Return is true only when remaining flags are zero.

Overflow first requests status generation, then compares the supplied result with zero. The original strict-positive test is preserved; negative, zero and unordered are not positive. Rounding 0 chooses signed infinity, 0xC00 signed maximum finite, 0x400 positive maximum finite/negative infinity, and 0x800 positive infinity/negative maximum finite. Result bits come from Game.exe constants 0050F150 and 0050F160, without host overflow arithmetic or guessed saturation behavior.

Underflow copies the input through the existing x87 binary64 load boundary and preserves the input inexact flag. Zero/unordered forces inexact and **does not rewrite the original result pointer**. Other values call the translated 004F198A and subtract exactly 0x600 from its exponent. Values below -1074 take direct **positive zero**, even for a negative input, and force inexact. The other branch clears sign/exponent, preserves fraction bits and inserts bit 52, then shifts right toward exponent -1021 while recording discarded low bits. It restores sign only in this branch. The native two-DWORD shift is expressed as an equivalent logical uint64_t shift; no guessed frexp/scalbn operation is used. The result is stored before requesting underflow status when inexact, and input inexact may independently request precision status afterward.

## Decomposition

The initial zero comparison uses native equality/unordered semantics: signed zero and NaN take positive-zero/result-exponent-zero. The latter intentionally differs from host frexp. Ordinary nonzero inputs preserve original bits, pass their value through completed 004F1907 with exponent-field argument zero and return original exponent minus 0x3FE. Infinities consequently produce signed 0.5 and exponent 1025, rather than a host frexp infinity result.

Subnormal inputs compare sign again, initialize exponent to -1021 and shift the original high/low DWORD pair until bit 52 is set, decrementing exponent each time. The uint64_t translation retains sign-bit loss during shifting; the recorded negative sign is restored only after removing bit 52. This reconstructed bit pattern is passed through the original exponent-field child. The smallest positive subnormal consequently normalizes to 0.5/exponent -1073. These integer transformations are established by Windows instructions, not inferred from the Mac implementation or replaced with a standard library function.
