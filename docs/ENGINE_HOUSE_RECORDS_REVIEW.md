# Static and dynamic house graphics records

The complete 2,236-byte Windows house type record now has a physical model and named fields: edit name/groups, five logic types/stages, build/walk/work areas, construction goods, door positions, hitpoints, arrow slots, borrowed bob managers/palettes, shading, stage images, door overlays, construction layers, action/landscape overlays and five point/flag groups. Nested models retain the original fixed capacities and padding. The arrow-slot parameter remains unclassified rather than receiving an unsupported interpretation.

Drawing, loading and owned-resource destruction reuse these definitions. The stage-dependent point view preserves the original shifted receiver (`record + stage * 52`) and root-relative offsets; it is not confused with the physical fifty-two-byte stage record. Construction layers retain separate image and shadow IDs plus percentage bounds. Action overlays are distinct from landscape overlays even though both have fields at zero/four/eight.

Dynamic house records remain 208 bytes: active-fire count, 200 flags, selection byte and three padding bytes. Construction clears the complete record; the logic sound callback clears only its original 204-byte prefix. Save/load uses that same prefix and keeps selection outside the saved payload. No ownership, allocation or object lifetime is changed by the models.

Windows evidence: `0048E651..0048F6E8` and drawing/effect routines `00495B57..00496C8A`. Preserved: constructors before array clearing, token/read order, unvalidated stage counting pass, fixed limits and original missing bounds checks, area/list ownership and free order, palette choice, effect/overlay ordering, integer percentage arithmetic, one fire-point update per draw, RNG call order, sign ordering and display-dependent debug/visibility behavior. The separate [door activation correction](HOUSE_DOOR_OVERLAY_FLAG_FIX.md) was committed before this naming block; the naming baseline already contains that Windows-confirmed correction. Mac provides names only.

Validation: exact staged source/token equivalence, 107 numeric value/type comparisons, 38 physical size/offset assertions, five affected production units and the private assertion unit passing Win32 `/Zs`, and 2,516 decoded instruction byte comparisons with original `Game.exe`. The companion CSV records 214 named references. No build, tests or game execution occurred. Remaining parser expression operands and other engine types remain review targets.
