# Diplomacy, inhabitants and statistics window records

Diplomacy names the page state, player count/IDs, hidden-tab flags, visible count, button-update tick, mission strings, overview rectangle and child. The 248-byte physical model covers the complete window. The selected-player lookup has a separate page-slot view: index zero overlays the count; positive page indices address the following player IDs. Diplomacy network commands use two player fields, not the ordinary actor ID/revision interpretation.

The inhabitants window model is 4,120 bytes: base window, count, 500 eight-byte ID/revision references and the job chooser pointer. The 120-byte chooser has its own owner pointer and current/possible-job mode byte. The 72-byte inhabitant button retains its separate human ID/revision, pressed/double-click commands, callback handler and debug byte. Function-specific receiver scopes prevent chooser fields from being mislabeled as the parent list's fields.

The statistics model is 620 bytes. Named fields cover three list pointers/update ticks, borrowed drawing bitmap pointers, dimensions/player, observed and display extrema, and twelve four-byte colors. Its embedded diagram constructor receives root +136; relative color offset 36 gives root +172. The remaining 400-byte tail stays explicitly unresolved. It is cleared by construction; this review does not assign it an unsupported purpose.

The complete class-static regions are described by separate models and named consumers: diplomacy page (4 bytes), inhabitants filter bytes/current-job/possible-job selection (24 bytes), statistics page/good group/time scale in hours (12 bytes). Unclassified filter slots remain byte-array positions. Save/load retains all 24 inhabitants bytes; diplomacy/statistics persist their original page word only. Network-session, chunk-version and skip behavior are unchanged.

Windows evidence: `004AEF6A..004B1B76` and `004B1B77..004B3263`. Preserved: callback registration/unregistration order, subwindow reuse and close handling, human cap/filter/hero-name sorting and revision validation, both query branches writing the possible-job field, retained hidden/overview state, mission string destruction, tab reset order, stored draw pointers, diagram extrema/rounding behavior, list scroll retention and update timers. Existing floating-point precision differences remain documented; this naming pass does not change them. Mac is a naming reference only.

Validation: exact staged baseline/token equivalence, 61 literal value/type comparisons, 51 physical size/offset assertions, five affected production units and the private assertion unit passing Win32 `/Zs`, and 5,670 decoded instruction byte comparisons with original `Game.exe`. The companion CSV records 191 named references. Formatting changes only whitespace. No build, tests or game execution occurred; whole-source review remains incomplete.
