# Remaster bug fixes and community comparison

Reviewed October 16, 2026 on `remaster`, starting from `1f33a7d`.

## Branch policy

The user has frozen `reversed-game-authentic-behaviour` at `b15e6ff` as the legacy implementation, including original defects. Its code and [original-behavior register](RECONSTRUCTION_NOTES.md) remain unchanged. The register is historical evidence, not an active remaster status list. All intentional corrections below belong only to `remaster`; future work must follow the same separation.

The register contains 97 OB entries and 156 OA entries, not 253 independently reproduced bugs. Existing reconstruction corrections and intentional usability changes are tracked separately in [gameplay issues](GAMEPLAY_RENDERING_BUG_REVIEW.md). This ledger does not retroactively relabel those as original bugs.

The user explicitly excluded networking from this block and reserved its bugs and modernization for a separate later refactoring project. All network-related comparison rows below are analysis only and deferred, including host-input loss, stability, transfer size, version checks, multiplayer music/options and logging. No network implementation was changed. The [player changelog](CHANGELOG_REMASTER.md) describes the completed source changes; it is not a claim that the whole historical register is resolved.

## External comparison

Reference: [Basssiiie/cultures-saga-patches](https://github.com/Basssiiie/cultures-saga-patches), inspected commit [`ead57f3c618c8e2199979c4ae7d2d718baedd85e`](https://github.com/Basssiiie/cultures-saga-patches/tree/ead57f3c618c8e2199979c4ae7d2d718baedd85e). Its 24 patch modules were downloaded for inspection only; the patcher was not run. It targets a different executable revision. Its numeric offsets must not be copied into this project's Windows reference binary or treated as matching addresses.

Six modules explicitly name bug fixes. Their overlap with our records is:

- Marker allocation is a direct code-path overlap with OA130: the original reserves a slot and rejects a valid border point before initialization. The community report identifies a border-marker crash, including AI guide use. This same rejection is present in our Windows reference.
- Particle access outside the map is already recorded in the gameplay review, outside the OB/OA catalog. Our checked accessor prevented the invalid read; RM005 below completes retirement of the escaped particle.
- School is related to OA163, but the mechanisms differ. The community patch disables general job/good eligibility based on the current training counter. OA163 concerns independent current-job working-experience events during schooling. RM001 fixes the former; it does not claim to resolve the latter.
- Vehicle-builder freeze, attack-radius freeze and host input loss are not separately identified as exact defects in our OB/OA catalog. Broad task/path/network observations cover their surroundings but are not proof that those exact bugs were already listed.
- None of these six modules directly fixes OB089's player-count/message-length copy error, OB044/OB090's event-counter errors or the other specific OB audio/CRT findings. Shared subsystem names are not an exact overlap.

## Remaster input cleanup

RM010 removes the unused `CDirectInputMouse` implementation/header and `LegacyDirectInput.def`, their project/filter entries, `dinput8.lib`, the generated import library and its generation target, and the Win32 symbol alias for `DirectInputCreateA`. Before removal, all class and DirectInput API references were confined to that obsolete module. Application startup already constructs `CMouseManager`, whose active input uses Windows Raw Input and cursor/button/wheel messages. No active input source or object layout is changed. Shared DirectX error-name constants remain available to the common diagnostic formatter; their presence does not imply a DirectInput dependency.

This is removal of superseded remaster code, not another original-game bug fix. The legacy branch retains its original mouse implementation and build setup. The project and filters now agree on 306 CPP files and 287 headers, all present in `src/`. Source/reference and XML inventory checks pass; build/link and gameplay checks were not run. The original reconstruction-entry total remains a historical checkpoint.

## Verification and boundaries

- The five gameplay evidence ranges for marker allocation, both education queries, vehicle-builder startup, attack startup and particle sorting match **1,173** ASM instruction byte sequences against the reference Windows `Game.exe`. Five additional audio ranges match **447** instruction sequences. These **1,620** matches verify original evidence provenance, not runtime correctness of the intentional changes.
- School, marker and attack patch expected bytes match their mapped Windows locations. The vehicle branch has the same JNZ-to-epilogue structure with a different relative displacement; no assumption of a single global address offset was used.
- Six implementation units pass Win32 MSVC `/Zs /W4` without warnings: job access, vehicle jobs, human initialization, attack tasks, particle drawing and DSManager. No Debug/Release build, linking, new tests or agent-run game session was performed.
- The original branch still points to `b15e6ff4c43aaf6e3ba33f4ebfbd035d8575b0cb`; the historical register is byte-identical to that branch. Scratch evidence, downloaded reference sources and syntax logs are under `.codex-work/community-patches/` and `.codex-work/audio-remaster/`.
- The separate scout-radius working-tree edit is outside this correction block and must remain separate when committing `C2HumanJobAccess.cpp`.
- Both peers must use a compatible remaster revision when validating changed deterministic gameplay. The community patch's network version number is not adopted.

The current source-correction block is complete. Its next step is targeted gameplay/audio validation after a user-requested build. OA163 and the remaining OB/OA findings remain open for separate evidence-led work. Network initialization, command/event ownership (including OB089, OB044/OB090 and OA017), transfer integrity and locking are reserved for the later network refactoring project.
