# Windows math-error dispatcher - 2026-10-11

## Defined exception metadata and C4700 correction - 2026-10-13

The reported uninitialized-record warning exposed C++ reads of indeterminate metadata in the exceptional false-return branch of the masked-response helper. The parent now initializes four DWORDs before their read/modify/write operations: `controlAndOperation` and the flags for operand1, operand2 and result. Cause/enable/status remain supplied by the IEEE child; unused operand values, value tails and padding remain untouched. The previous claim below that volatile preserves unspecified native stack bits is historical: volatile does not make an uninitialized C++ read defined.

Windows `004F04D7/004F04DD` confirms that the native stack metadata is unspecified, and `004F1AEF` supplies rounding, precision, operation, valid/format, exception-status and value fields. This correction deliberately gives the four previously unspecified metadata words a zero baseline; their reserved bits no longer reflect arbitrary stack contents. Defined flag masks, operation-specific argument2 handling, IEEE handler invocation and resumed result/control propagation retain their order. This is a C++ correctness adjustment to undefined metadata, not a claim of identical unused stack bytes.

The three-unit warning audit also verifies C4805/C4799 and 166 native GUI/CRT instruction byte sequences. A separate existing C4334 at the mantissa increment remains visible under `/W3`. No requested warning is suppressed; no Debug/Release project build, tests or game run occurred.

The 0x20-byte native error record has signed type at +0, name pointer at +4, binary64 argument1/argument2/result at +8/+0x10/+0x18. Compile-time size and offset checks enforce the Win32 layout. No richer unknown union, allocation or ownership is invented. The name is descriptive of the Windows-proven record; the Mac private CRT counterpart is not established.

004F046B reads the caller's saved **16-bit** control word once, zero-extends it into a local DWORD and leaves the caller's word unchanged. Error types 1/5, 2, 3, 4 and 8 produce math flags 8, 4, 0x11, 0x12 and 0x10 respectively. Type 7 becomes type 1 and skips masked response and IEEE raising. Other types also skip those calls. The original type and flag domains remain distinct.

For a mapped type, the dispatcher calls 004F1DA2 with flags, result pointer and the local saved control DWORD. Only a false return constructs the native 0x58-byte IEEE record and calls the completed 004F1AEF. The original stack record is not initialized wholesale; volatile accesses preserve the native read/modify/write of unspecified flag bytes rather than introducing zero defaults. Operation IDs 0x10/0x16/0x1D read the old operand2 flags, load/store argument2 through the existing x87 binary64 boundary, then apply `(flags & 0xFFFFFFE3) | 3`. Other operations clear operand2 validity only. Value tails, padding and unrelated record bytes are not written by this parent. The existing IEEE child supplies its remaining fields and observes any resumed-handler result/control changes.

The dispatcher next loads the local, potentially handler-updated raw control word through 004F2001 with mask 0xFFFF. This restoration precedes the original policy check, default math hook and errno update. Type 8 bypasses the hook. Other types call the completed default hook 004F1FE1 only when original data DWORD **0050F250** is zero; a nonzero hook return skips errno. The current default hook returns zero. The existing 004F1FB9 sets EDOM 0x21 only for type 1, ERANGE 0x22 only for types 2/3 and leaves other types unchanged. In particular, types 4/5/8 are not silently given a different errno policy.
