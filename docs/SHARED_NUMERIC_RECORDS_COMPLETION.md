# Shared numeric input tagging and conversion records - 2026-10-11

Two Windows entries are reconstructed; see [SHARED_NUMERIC_RECORDS_NATIVE_ENTRIES.csv](SHARED_NUMERIC_RECORDS_NATIVE_ENTRIES.csv).

004ED0B7 converts a decimal string through existing 004F0D65 extended parsing and 004F0A07 binary64 conversion. The 0x18-byte output record contains flags at +0, consumed character count at +4 and a binary64 value at +0x10. Bytes +8..+0xF remain untouched. Parser bit 4 sets invalid-input flag 0x200 and positive zero, skipping binary conversion. Otherwise parser bit 2 or conversion status 1 sets overflow flag 0x80; parser bit 1 or conversion status 2 adds underflow flag 0x100. Consumed count uses the wrapped 32-bit end-minus-start address difference. Original store order is flags, value, count; the captured destination pointer is returned. Static assertions enforce size/value offset. Existing ordinary C++ double loads/stores represent the binary64 copy; precise pending x87 exception delivery remains a wider unresolved runtime constraint, not a claim of binary identity.

The existing Runtime_StringToDouble entry 004E82A6 now calls this distinct helper instead of retaining only a private subset of its logic. After leading whitespace, Windows calls strlen 004E5D10 before its helper; that string read is restored. Native caller stack slots carrying length and two zeros are not read by the helper and do not invent new parse options. The final returned number remains the helper's +0x10 value. No host strtod dependency is substituted.

004EB7C8 is an integer-only helper: it reads the input's upper DWORD, isolates exponent bits, and returns the original high DWORD only for exponent 0x7FF. It does not load the argument into x87, perform a floating comparison or quiet a signaling NaN. The C++ implementation uses byte copying and integer masks. Its native comparison also feeds the following math continuation's equality branch; when those still-unresolved parent continuations are reconstructed, that branch must explicitly compare the tag's exponent mask. The native x87 wrappers for log10, sin, cos and atan invoke it after storing their x87 argument. Those parents remain open; numeric host adapters are not promoted to complete because this leaf is now available.

The original CRT helpers have no established Mac implementation correspondence; their names describe Windows-proven operations. No inline assembly, build, tests or game run were added. Primary and integrating syntax checks and the fresh inventory are recorded in the checkpoint.
