# Windows human military and assistant state

Reviewed 2026-10-13 against Windows x86 assembly and the original `Game.exe`.

The military mode at human +0xB5C is a DWORD. The following byte at +0xB60 controls world refreshment: command 42 writes its Boolean parameter after checking atomic interruptibility. The getter at 0042CC12 and the needs dispatcher at 00463509 establish its meaning. Item use precedes the flag check; automatic interruption to fulfill urgent needs requires the flag. Eating and sleeping also consult it. `SetMilitaryAggressiveFlag` was misleading and is now `SetMilitaryWorldRefreshmentFlag`, retaining opcode 42. The Mac declaration supplies that original command name only; no Mac layout or behavior was used.

Primary and secondary military targets occupy two separate 12-byte records at +0xB64 and +0xB70. The primary value is an object ID for object targets or a packed point for a landscape target. Its third DWORD is the object revision and is cleared for landscape commands. Secondary targets come from enemy searches or incoming attackers. Primary does not mean exclusively user-selected: landscape search can write it too. Mode 3 clears the secondary target. Both records and their attack priority remain distinct. Attack write order, interruptibility checks and the original type/revision comparison that omits object ID are preserved.

Assistant data starts at +0xB88 and occupies 208 bytes, ending at the 0xC58 human record boundary. Windows 0044057D clears those 208 bytes and sets the initialization byte. The history-present byte is relative +4 (human +0xB8C); the renderer reads it for the assistant-history icon. Relative +8 contains ten 20-byte command-history records: command, two parameters, start tick and duration ticks. Duration is multiplied by 720. The unit supplied by callers is kept as `TicksPerDurationUnit`, without assuming seconds.

History insertion validates first, selects the first empty slot, otherwise the first strictly earliest expiry. Unsigned addition/comparison, ties and the UINT32_MAX index sentinel when all expiry sums equal UINT32_MAX are unchanged. Validation clears only expired command DWORDs and updates the history-present flag only after a change. The original six assistant functions remain separate; condensed branches in insertion and validation now use explicit blocks.

Named 85 human scalar/base accesses in 14 units, plus assistant records, their GUI/AI consumers and target strides. The primary access inventory is `HUMAN_MILITARY_LAYOUT_ACCESS_MAP.csv`; assistant relative members are listed above and in `C2ObjectLayout.h`. First-parameter human interfaces and whole human-array pointer flow establish receivers; no offset was applied to an unverified folded constructor.

Win32 `/Zs` passes for all 17 affected C++ units and 26 compiler value/type pairs. Three layout assertions establish target adjacency, history size and the human boundary. Exact staged source comparison and targeted instruction-byte verification against `Game.exe` pass for 921 instructions. Whitespace-only expansion of the two assistant branches preserves their statements and order. No build, tests or game run occurred. These checks support the refactor, not a claim of complete runtime equivalence.

The whole-source review continues. Human task counters/timers, sector links, specialized flag bytes and the remaining engine/GUI/control/data layouts still need complete xref review.
